## Где конкуренты сильнее

Честно, без скидок:

1. **Готовые патченные сборки Chromium.** Не зависят от того, какой Chrome стоит
   у пользователя, и полностью контролируют нативный слой. Mirage работает
   поверх штатного Chrome: меньше контроля, зато нет «своей» сборки, которую
   надо поддерживать и которую антифрод изучает отдельно от штатного браузера.
2. **Зрелый cookie-робот.** У всех четверых есть прогрев профилей по cookie.
   У Mirage пока нет даже импорта cookie (волна 2).
3. **Магазины расширений** и готовые интеграции (наличие по каждому — проверить).
4. **Поддержка 24/7** с живым чатом. У Mirage — GitHub issues, без SLA.
5. **Мобильные эмуляции** из коробки. У Mirage — волна 3.
6. **Командные фичи сразу.** Облачный синк работает из коробки, без своего
   сервера.

## Почему Mirage

1. **Открытость.** Ядро под MIT: можно аудировать, что именно подменяется, что
   читается и что уходит наружу. Закрытые аналоги требуют доверия на слово.
2. **Локальное шифрование.** Профили — AES-256-GCM на диске, ключ выводится из
   пароля (Argon2id). Облачного хранилища нет по умолчанию.
3. **Seed-воспроизводимость.** Одинаковый seed = одинаковый фингерпринт на любой
   машине. Отладка, регресс-тесты, командная работа: коллега воспроизводит
   профиль по seed, не передавая данные.
4. **AdsPower-совместимый локальный API (волна 2).** Скрипты, написанные под
   AdsPower Local API, работают с Mirage без переписывания — миграция без боли.
5. **Self-hosted синк (волна 2–3).** Командная синхронизация на своём сервере:
   профили не проходят через чужое облако.

Сегодня закрытые аналоги готовы к бою, Mirage — волна 1 в разработке: ядро без
UI/CLI/API. Когда что появится — [ROADMAP.md](ROADMAP.md).
