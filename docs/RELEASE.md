# Release

Чек-лист сборки и публикации релиза Mirage. Единый источник версии — строка
`version` в `[workspace.package]` корневого `Cargo.toml`: все крейты наследуют
её (`version.workspace = true`), её же читает `scripts/package.ps1`.

## Подготовка

1. Поднять версию в `[workspace.package]` корневого `Cargo.toml`.
2. Подготовить заметку о релизе: что вошло, breaking changes, известные
   проблемы. Файла `CHANGELOG.md` в репозитории пока нет — до его появления
   заметка идёт в черновик GitHub Release и в описание релизного PR.
3. Убедиться, что рабочее дерево чистое. `release.ps1` предупредит о
   незакоммиченных файлах, но не заблокирует прогон; в архив при этом может
   попасть недокоммиченный контент. Релиз — из чистого чекаута.

## Прогон конвейера

```
pwsh scripts/release.ps1
```

PowerShell 7, права администратора не нужны. Каждый шаг — в своём try/catch,
все шаги выполняются даже после сбоя предыдущего, в конце — сводка. Exit code:
`0` — всё зелёное, `1` — есть упавшие шаги, `2` — проблема окружения
(cargo не найден, это не чекаут Mirage).

| # | Шаг | Комментарий |
|---|---|---|
| 1 | чистота git | незакоммиченное — warn, не блокирует; нет репозитория/git — info |
| 2 | `cargo fmt --all -- --check` | соответствие rustfmt.toml |
| 3 | `cargo clippy --workspace --all-targets -- -D warnings` | любой lint = ошибка |
| 4 | `cargo test --workspace` | офлайн: локальные порты, Chrome не запускается |
| 5 | `cargo build --release --workspace` | thin LTO + codegen-units=1, первый прогон небыстрый |
| 6 | `scripts/package.ps1` | отдельным процессом; собирает zip |

## Ручная проверка перед публикацией

1. Smoke на живом Chrome: `cargo run -p mirage-launcher --example smoke` —
   spawn Chrome из seed-профиля, сверка легенды и антидетект-инвариантов
   (worker scope, toString-маскировка, descriptor hygiene, blank-canvas,
   DPR/media queries, геометрия окна, GREASE brands). Все строки — PASS.
2. Adversarial e2e при `MIRAGE_E2E=1` — обвязка волны 2 (см. ROADMAP): живой
   прогон запускается только при выставленной `MIRAGE_E2E=1`
   (`cargo test -p mirage-e2e -- --ignored`); переменная читается в
   `crates/mirage-e2e/src/lib.rs`.
3. Живой прогон whoer.net по методике [DETECTION.md](DETECTION.md) — критерий
   готовности волны 1 (язык, таймзона, IP, WebRTC без противоречий).

## Упаковка

`scripts/package.ps1` (шаг 6 конвейера; можно и отдельно) читает версию из
`Cargo.toml` и собирает `dist\mirage-<version>-win-x64.zip`:

| Путь в архиве | Источник |
|---|---|
| `mirage-<version>-win-x64\bin\*.exe` | бинари крейтов из `target\release`; examples не включаются |
| `...\README.md`, `...\LICENSE` | корень репозитория |
| `...\docs\` | вся документация, включая CONTRACT.md (пользовательская) |
| `...\inject\` | JS-спуф слой (для переопределений вида `MIRAGE_INJECT_DIR`) |
| `...\fp-db\README.md` | заметки по базам фингерпринтов |

Скрипт печатает состав и размер архива. Если в `target\release` нет ни одного
exe — warn и архив без `bin\`: в волне 1 workspace библиотечный (`[[bin]]`
целей нет), поэтому zip волны 1 — дистрибуция документации и спуф-слоя,
а не готовый продукт.

## NSIS-инсталлятор

Сборка (NSIS 3.x, `makensis` в PATH, из корня репозитория; `dist\` уже создан
`package.ps1` или вручную):

```
makensis installer\mirage.nsi
makensis /DMIRAGE_VERSION=X.Y.Z installer\mirage.nsi
```

- Ставит в `C:\Program Files\Mirage` (`$PROGRAMFILES64`), пишет деинсталлятор
  и запись в «Установка и удаление программ», лицензионная страница MIT,
  ярлыков нет — CLI/API-продукт волны 2.
- **NSIS-сборка в этой среде не тестировалась: makensis не установлен.**
  Перед первым реальным релизом — обязательная сборка и проверка на машине
  с NSIS (чек-лист ниже).
- Волна 1: строка `File ..\target\release\*.exe` не найдёт файлов, пока нет
  бинариев волны 2 — makensis прервётся с «no matching files». Это ожидаемо.

Проверка на чистой машине после сборки инсталлятора:

- установка проходит в `C:\Program Files\Mirage` без ошибок;
- файлы на месте: exe (когда появятся), README.md, LICENSE, `Uninstall.exe`;
- ярлыков нигде не появилось (их и не должно быть);
- «Установка и удаление программ»: Mirage с верной версией; деинсталляция
  удаляет папку и запись, `%LOCALAPPDATA%\Mirage` (профили, vault) остаётся
  нетронутой;
- повторная установка поверх существующей переиспользует прежний каталог
  (`InstallDirRegKey`).

## Публикация

1. `git tag vX.Y.Z` и push тега. Репозиторий сейчас без git-истории — теги
   появятся вместе с инициализацией репо.
2. Прикрепить `dist\mirage-X.Y.Z-win-x64.zip` к GitHub Release (черновик).
3. NSIS-сетап — в релиз только после ручной проверки на чистой машине.
4. Текст релиза — из CHANGELOG-заметки (см. «Подготовка»).

## Известные ограничения обвязки (2026-11)

- Бинариев нет (workspace library-only): zip без `bin\`, NSIS-скрипт не

- makensis отсутствует: инсталлятор не тестирован.
- git-репозиторий не инициализирован: теги и CI-релизы отложены.
