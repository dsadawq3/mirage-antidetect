# Mirage

Антидетект-браузер с открытым ядром: менеджер профилей поверх **штатного** Chromium,
движок фингерпринтов с воспроизводимостью из seed и шифрованное локальное хранилище.

> **Статус:** волны 1 (ядро) и 2 (продукт) реализованы: ядро, спуф-слой и
> патчи-шаблоны, локальный REST API, CLI, UI, cookies, импорт из конкурентов,
> sync-сервер, Python SDK, e2e-чекер и упаковка. Волна 3 (командная
> синхронизация с ролями поверх sync-сервера, мобильные профили, автообновление
> калибровки Chrome) — план; cookies-запись в нативный cookie-store и нативные
> патчи требуют реального прогона. План и критерии готовности —
> [docs/ROADMAP.md](docs/ROADMAP.md).

## Что это

Mirage решает одну задачу: браузерная сессия, у которой фингерпринт непротиворечив
и принадлежит легенде профиля, а не реальной машине.

- Профиль = фингерпринт + прокси + отдельный user-data-dir.
- Фингерпринт генерируется из seed по базам реальных значений (GPU, шрифты, экраны,
  локали) и до запуска проходит валидатор консистентности.
- Маскировка в два слоя: JS-инъекция через CDP (до скриптов страницы) и нативные
  патчи Chromium для того, что из JS подменять опасно (шрифты, чтение canvas).
- Профили шифруются на диске (Argon2id + AES-256-GCM). Облако не используется.

## Архитектура

```
   UI (Tauri) / CLI / REST API          <- волна 2; локальный API совместим с AdsPower
                  |
                  v
   mirage-core                          <- seed -> Fingerprint; валидатор консистентности
   fp-db/                               <- базы реальных значений: GPU, шрифты, экраны, локали
                  |
        +---------+---------+
        v                   v
   mirage-vault        mirage-launcher
   Argon2id + AES-     аргументы Chrome,
   256-GCM, .mprof     spawn, CDP-клиент
                           |
                           +-- mirage-proxy   <- SOCKS5 / HTTP-CONNECT, проверка exit-IP
                           v
                  Chromium (штатная сборка пользователя)
                     +-- inject/    <- JS-слой: спуф до скриптов страницы (через CDP)
                     +-- patches/   <- нативный слой: то, что из JS детектится
                                     (шрифты, чтение canvas)
```

## Быстрый старт

Сборка и тесты:

```
cargo build --workspace
cargo test --workspace
```

Требования: Rust (edition 2021), установленный Chrome (лаунчер ищет его сам),
Windows — пути и нативные патчи волны 1 рассчитаны на Windows.

Профили и хранилище:

```
%LOCALAPPDATA%\Mirage\
  vault\<id>.mprof      зашифрованный профиль (AES-256-GCM)
  vault\.vault.salt     соль Argon2id (создаётся при первом открытии хранилища)
  profiles\<id>\        user-data-dir Chromium
```

Пароль хранилища вводится при открытии; ключ выводится Argon2id из пароля и соли.
Без пароля `.mprof` не расшифровывается.

Синк-сервер (`crates/mirage-sync`): self-hosted синхронизация команд на
axum + SQLite с Bearer API-ключами. Тела профилей шифруются на диске
опционально — `MIRAGE_SYNC_KEY` (64 hex-символа = сырой ключ, иначе passphrase
через Argon2id), на диске `enc:v1:` + AES-256-GCM; без ключа тела хранятся
открытым текстом и сервер печатает предупреждение. Bootstrap-ключ админа
задаётся через `MIRAGE_SYNC_BOOTSTRAP_KEY` (в лог не попадает) или
генерируется и печатается один раз в stderr. Не-loopback bind запрещён без
`MIRAGE_SYNC_ALLOW_REMOTE=1`. Детали — `crates/mirage-sync/README.md`.

Проверка маскировки готового профиля — чек-лист в [docs/DETECTION.md](docs/DETECTION.md).

## Структура репозитория

| Каталог | Содержимое |
|---|---|
| `crates/mirage-core` | структуры Fingerprint/Profile, генератор из seed, валидатор консистентности, загрузка fp-db |
| `crates/mirage-vault` | шифрованное хранилище профилей (Argon2id + AES-256-GCM), файлы `.mprof` |
| `crates/mirage-proxy` | клиент SOCKS5 (RFC 1928/1929) и HTTP-CONNECT, проверка exit-IP |

| `crates/mirage-api` | локальный REST API (волна 2): профили, запуск/стоп, прокси, cookies, импорт, AdsPower-алиасы; HTTP-контракт — `docs/API.md` |
| `crates/mirage-cli` | CLI `mirage`: профили, запуск/статус/стоп, прокси, cookies, импорт, фингерпринты |
| `crates/mirage-cookies` | импорт/экспорт cookies из cookie-store Chromium (Netscape/JSON) |
| `crates/mirage-import` | импорт профилей из AdsPower, Dolphin Anty, GoLogin |
| `crates/mirage-sync` | self-hosted sync-сервер: SQLite, API-ключи с ролями, ревизии профилей |
| `crates/mirage-e2e` | offline e2e-чекер спуф-слоя (живой прогон под `MIRAGE_E2E=1`) |
| `fp-db/` | JSON-базы реальных значений: GPU, шрифты, экраны, локали |
| `inject/` | JS-спуф слой (исполняется до скриптов страницы) |
| `patches/` | нативные патчи Chromium (второй, усиливающий слой) |
| `sdk/python/` | Python SDK для локального API (только stdlib) |
| `ui/` | десктоп-панель на Tauri 2 |
| `docs/` | CONTRACT.md (карта модулей, обязателен к прочтению), API.md, ROADMAP, DETECTION, COMPARISON |
| `scripts/`, `.github/` | smoke-скрипты и CI |

## Статус

- **Волна 1 — ядро (реализована):** mirage-core, fp-db, mirage-vault,
  mirage-proxy, mirage-launcher, `inject/`, `patches/`, CI и smoke-скрипты.
- **Волна 2 — продукт (реализована):** локальный REST API с совместимостью с
  AdsPower Local API, UI на Tauri, CLI, cookie-импорт/экспорт, импорт профилей
  из Dolphin/AdsPower/GoLogin, self-hosted sync-сервер, Python SDK, e2e-чекер,
  упаковка.
- **Волна 3 — команда (план):** командная синхронизация с ролями поверх
  sync-сервера, мобильные профили, автообновление калибровки Chrome.

Cookies-запись в нативный cookie-store Chromium и нативные патчи (`patches/`)
требуют реального прогона: автотесты их не покрывают.

Детали и критерии готовности каждой волны — [docs/ROADMAP.md](docs/ROADMAP.md).

## Принципы

1. **Локальность.** Профили живут на диске пользователя зашифрованными. Ничего
   не уходит в облако: синхронизация (волна 2–3) — self-hosted и опциональна.
2. **Воспроизводимость из seed.** Одинаковый seed даёт одинаковый фингерпринт на
   любой машине: отладка, регресс-тесты и командная работа без расхождений —
   коллега воспроизводит профиль по seed, не передавая данные.
3. **Честная консистентность легенды.** Валидатор не пропускает противоречивые
   комбинации: Direct3D-рендерер на macOS, таймзона мимо локали, client hints
   мимо UA. Полный список правил — [docs/CONTRACT.md](docs/CONTRACT.md).
4. **Два слоя маскировки.** JS-слой через CDP для стандартных полей; нативные
   патчи для того, что из JS детектится (перечисление шрифтов, чтение canvas).
   Список сознательных отказов от JS-подмены — [docs/DETECTION.md](docs/DETECTION.md).

## Как контрибьютить

1. Прочитайте [docs/CONTRACT.md](docs/CONTRACT.md) — контракт данных и модулей
   обязателен буква-в-букву: имена полей, типы, пути, порядок файлов спуф-слоя.
2. Правила кода: Rust edition 2021; production-код без TODO и заглушек; без
   `unwrap`/`expect` в библиотечном коде (только в тестах); юнит-тесты для
   нетривиальной логики; комментарии на английском, по делу.
3. `cargo test --workspace` должен быть зелёным.
4. Изменения контракта — отдельным PR с обсуждением: контракт меняется редко и
   осознанно.
